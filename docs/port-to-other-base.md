# 把「问股」能力搬到另一个底座：交接说明

这份文档写给**下一个接手的 agent / 开发者**。目标不是把整个 App 搬过去，而是把「股票分析能力 + 工具层」搬进一个新的 AI 客户端底座。

---

## 0. 一句话

新底座负责聊天、模型、工具运行时、会话存储；我们要往里加的是**缠论结构分析、多级别取数、股票工具集、子智能体编排**，以及**数据口径与校验**。

---

## 1. 我们手上有两套实现，按底座语言选

| | Eta 问股（Kotlin） | mew 问股（Dart/Flutter） |
|---|---|---|
| 底座 | Eta（Android，Compose） | MewHub（Flutter） |
| 股票引擎 | `io.github.mangi.eta.chan`: `TdxFormula.kt`(909) + `Chanlun.kt`(516) | `lib/stock/`: `tdx_formula.dart`(~1050) + `chanlun.dart` |
| 取数 | `StockKlineSource.kt`、`StockIndicators.kt`、`StockLevels.kt` | `stock_source.dart`(~1100)、`indicators.dart`、`chart_context.dart` |
| 图表 | `StockChartPanel.kt`（Compose Canvas） | `stock_chart_panel.dart`（CustomPainter，~2100 行） |
| 工具 | 注册在 Eta 的 AgentToolRequirements | `lib/tools/stock_tools.dart` 9 个工具 |
| 子智能体 | 无（当时没做） | `lib/agents/`（上下文注入、分派、讨论、团队面板） |
| 验证 | golden 9 用例 + 真机截图核对 | golden ≥1e-6 逐值、10+7 单测 |

**结论**：新底座若是 Kotlin/Compose，拿 Eta 那套；若是 Flutter/Dart，拿 mew 那套。两边算法的口径是同一套（都对齐过 Python 参考实现），不要重新发明。

已验证的基准数字（改完必须能复现，否则就是改坏了）：

- 300274 日线 640 根：**38 笔 / 4 中枢 / 6 背驰 / 3 买卖点**，中枢 `183.86-158.95`、`140.80-123.49`，与通达信截图一致；
- 中枢数量随窗口：200→1、270→2、300→3、400/500/640→4（**400 根起收敛，一律取 640**）；
- 至少 210/211 个公式序列与 Python 参考实现逐值一致（1 个是浮点末位差）。

## 2. 选底座的硬条件（不满足就别选）

1. **工具运行时能拿到上下文**：工具在执行时至少能拿到当前模型、可用工具列表、取消令牌。没有这条，子智能体、多工具编排都做不了（mew 那边是靠 Zone 注入补的，属于补救而非设计）。
2. **工具可以被动态筛选**：能按会话/场景只暴露一部分工具（股票工具不该出现在写代码的场景里）。
3. **支持流式输出与工具循环**：一次回复里可以「模型 → 调工具 → 再问」多轮。
4. **本地文件或数据库持久化**：画线、自选、子智能体配置、分析缓存要能落盘。
5. **能自己加图表**：需要一个能画 Canvas/自定义绘制的面板位（K 线要手势：缩放、平移、长按十字）。
6. **许可证允许**：AGPL/GPL 可以（我们也是 AGPL），**PolyForm Noncommercial、SSPL、纯 MIT 的商业闭源二开要看清**。

## 3. 迁移顺序与验收（每阶段自己就能验）

**P1 取数与指标（不碰 UI）**
- 移植 K 线取数：腾讯 `ifzq.gtimg.cn` → 新浪 → 东财 三级降级，前复权口径要写明；一次最多 640 根。
- 移植指标：MA/EMA/BOLL/MACD/KDJ/RSI/VOL，口径与 `indicators.js`/Python 逐值对齐。
- 验收：给定 fixture，指标与参考实现误差 ≤1e-6；断网/坏 JSON 不崩。

**P2 缠论引擎**
- 移植 `TdxFormula`（公式解释器）+ `Chanlun`（笔/中枢/背驰/买卖点）。
- 验收：**38/4/6/3** 那条基准必须复现；至少 16 个序列逐值一致。
- 注意公式解释器已知 3 个坑（见 §4）。

**P3 工具层**
- 至少这几个：`stock_kline`、`analyze_chan`、`stock_quote`、`stock_levels`、`chart_context`、`chart_annotate`。
- 每个工具输出都要带 `data` 块：`source / adjust / as_of / closed / from_cache / quality`。
- 验收：工具能在一个真实对话里被模型正确调用，输出不超上下文预算。

**P4 图表与交互**
- K 线面板：手势（双指缩放基准必须建在**第二指按下**时）、十字光标、指标横条、缠论标注（背驰/买卖点/中枢）。
- 画线锚点机制：画线按「最后一根 K 线」打标，跨交易日或分钟线走出新 K 线即整组作废（不做逐根重定位）。

**P5 子智能体（可选，但很值）**
- 配置模型 + 分派工具 + 运行时（单任务 24 步、1 层嵌套、单工具 3 分钟）+ 过程可见。
- 验收：一次分派里 3 个任务并行，各自返回带 steps/耗时/token。

## 4. 已知坑清单（都是踩过的，直接抄结论）

1. **腾讯旧域名** `web.ifzq.gtimg.cn` 被 WAF 拦 501 → 用 `ifzq.gtimg.cn`。
2. **GBK**：新浪报价是 GBK，UTF-8 解会乱码。
3. **`month` 不能用 `startsWith('m')` 判成分钟线**。
4. **`jsonEncode(NaN)` 会抛异常** → 数值统一走四舍五入函数。
5. **背驰级别不能取全历史中枢数**（`boxes.length`），那是未来数据；要取 `e <= 当前索引`。
6. **买卖点选中枢用 `e<=idx` 会拿到旧框**，要用 `s<=idx` 并加高度约束。
7. **公式解释器三个真 bug**：按行切语句（应按时分号）、`EVERY` 把标量包成数组导致恒 0、解析后不检查 token 耗尽导致截断静默。
8. **窗口太短会在最左沿凭空造中枢**：只喂 270 根会多出一个框，必须喂 640 再裁可视窗口。
9. **画线坐标是 K 线索引**，滚动窗口会让它整体位移，必须按锚点整组作废。
10. **双指缩放基准**建在 touchstart 的「两指同时按下」分支里几乎永不成立，要建在第二指按下时。

## 5. 数据源与合规

| 用途 | 可用 | 说明 |
|---|---|---|
| 个股 K 线 | 腾讯 `ifzq.gtimg.cn`、东财、新浪 | 免费、非官方、无 SLA |
| 实时报价 | 新浪 `hq.sinajs.cn`、腾讯 | 免费，新浪需 `Referer` + GBK |
| 板块强度 | 东财 `push2.eastmoney.com/api/qt/clist/get`，`fs=m:90+t:2` | 实测可用，返回板块代码 BKxxxx、涨跌幅、主力净流入 |
| 指数 | 同行情接口（sh000001/sz399001 等） | 可用 |
| 涨跌家数 | 待验证 | 东财字段要另找，别猜 |
| 资讯 | 需自备（搜索服务或新闻 API） | 财联社旧路径已 404 |

**不做**：开盘啦/短线侠的题材与连板数据（第三方付费数据，靠硬编码密钥解密；既不合规也不体面）。

**原则**：取不到就说取不到，绝不编数字；每个结论都要能回到「什么时候、从哪个源、是不是缓存」这一层。

## 6. 给下一个 agent 的任务书（可直接粘贴）

> 你在维护 `<底座名>`（`<仓库地址>`）。我要把一套 A 股分析能力移植进来，源码在 `github.com/homestay377/mew-ask-stock`（Dart/Flutter 实现）与 Eta 问股的 Kotlin 实现（缠论引擎同一套口径）。
>
> **目标**：在这个底座的聊天里，模型能调用股票工具；面板能画 K 线与缠论结构；工具输出带数据来源与新鲜度。
>
> **不要做的事**：
> 1. 不要重写缠论算法，也不要"优化"它——先按原样移植，跑通基准再谈改；
> 2. 不要引入任何需要付费/破解的行情源；
> 3. 不要在取不到数据时用估计值填充。
>
> **验收标准（必须逐条给出证据）**：
> - 640 根日线 → 38 笔 / 4 中枢 / 6 背驰 / 3 买卖点，中枢 `183.86-158.95`、`140.80-123.49`；
> - 16 个公式序列与参考实现逐值一致（≤1e-6）；
> - 单测覆盖：空数据、坏 JSON、除权跳空、等比缩放 0.5/2/100 倍结构不变；
> - 工具输出含 `source/adjust/as_of/closed/from_cache/quality`。
>
> **先回答我三个问题再动手**：① 你的工具运行时能不能在执行时拿到当前模型与工具表？② 图表面板是自绘还是第三方库，能否加自定义标注？③ 会话/配置的持久化方式是什么？
>
> 细节读我给你的 `port-to-other-base.md`（本文），第 4 节是已知坑，别重新踩一遍。

## 7. 交接时必须说清的边界

- 我们**没有**指数、板块、涨停、新闻的稳定数据源（除板块已实测可用），所以不要承诺"市场情绪分""连板梯队"这类功能；
- **不做**账户/持仓/组合（没有券商数据，做了就是假的）；
- iOS 只能出未签名包，真机要自己签；
- 所有"看起来像结论"的东西都要带证据字段，这是这个项目唯一的底线。
