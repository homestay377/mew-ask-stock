# mew 问股 v1.10.11

## 团队运行中，你说的话终于有地方去了

上一版在输入框上方加了「团队运行中 · 发送的消息会直接交给团队」这条横幅。问题是它说得不实：`dispatch_subagents` 还在跑的时候，主对话的生成循环被它占着，用户此时发消息只会排队，团队根本收不到。

这一版开出独立通道，横幅说的话现在是真能做到。

### 1. 追问通道 `team_lead`

新增 `lib/agents/team_lead.dart`：拿**当前任务板快照** + 用户问题，用同一个模型做一次独立生成，允许调用 `add_team_tasks` 追加任务，最多 3 轮工具调用。

`ChatController.askTeam()` 负责接线：主对话被占用时也能问，回答直接回面板。

面板里的用法：

```
你
t2 那个研究员的结论可信吗？

lead
t2 目前只跑了 3 步、还没给出结论；它的产出会随「依赖 t1」自动接上。要更稳的话我可以追加一条核验任务。
```

问答记录留在面板「团队会话」区，不会把你踢回主界面。

### 2. 任务板快照的体积上限

`board` 会随 `ToolPart.meta` 每 120ms 更新一次，而会话每 3 秒把整份 JSON 落一次库。不裁剪的话，一次长任务就能把库撑到几 MB，读写都变慢。

现在限制为：

| 字段 | 上限 |
|---|---|
| `steps` | 最近 8 条 |
| 单步 `output` | 400 字 |
| 任务 `output` | 2000 字 |
| 实时 `liveOutput` | 2000 字 |

完整原文仍在工具返回的 JSON 里，快照只是给界面看的。

### 3. 协作步骤露脸

卡片里的步骤行现在优先显示协作类：

```
· 问主控 ✓ 那条背驰力度不够，先看 60 分
· 申请工具 ✓ 已开通 stock_levels
```

`ask_main_agent` / `ask_peer` / `request_capability` 比再列一条 `http_request` 有用——它说明子智能体卡在哪、怎么解的。

## 顺带确认的一件事

「trace 持久化」这条不用做：`ToolPart.toJson` 本来就带 `meta`，`Conversation.toJson` 又整份 `jsonEncode` 进库，所以 `meta.board` 一直随会话落盘。重启后历史消息里的任务板仍在。

清水的 `MAX_LIVE_TRACES = 16` 那种 LRU 也不需要——他们的实时态在内存 StateFlow 里，我们放在消息的 meta 上，天然跟着会话走。
