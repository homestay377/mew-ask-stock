## 1. 快捷短语：预置 8 条「分析方法」

之前那 8 条是「看什么」（日线结构、多周期、位置判断…），这次补的是「用哪套方法看」——每条都指定了工具、计算口径和输出格式。

| 短语 | 指定了什么 |
|---|---|
| **全量分析** | 五步走：多级别取数 → 缠论结构 → 量价关系 → 位置判断 → 结论含失效位 |
| **缠论结构** | 只用 `analyze_chan`：笔的递进、中枢 ZG/ZD 带日期、背驰 level 与面积比（要求自己算一遍）、买卖点依据；必须写明 `repaints=true` |
| **量价背离** | 三种背离的判定条件，要求用 MACD 红绿柱面积佐证，并明确说「放量突破/缩量反抽/放量下跌/缩量整理」哪一种 |
| **多周期共振** | 列各级别 trend 与 last_date，指出哪两个相反；`bars_adequate` 不足 400 根要打折扣 |
| **支撑压力** | 三层依据（中枢 ZG/ZD、60 日高低点、成交密集区），每条写清怎么算的 |
| **买点复核** | 查买卖点引用的中枢是否已走完（不是未来数据）、背驰力度够不够、信号后是否失效 |
| **风险排查** | 数据风险（is_intraday/缓存/根数）+ 结构风险 + 量能风险，逐条给证据 |
| **对比分析** | 先用 market_overview 找同板块，再 scan_stocks 一次扫三只做结构对比 |

合计 16 条（8 场景 + 8 方法），只装一次，删了不会回来。

## 2. 「今天涨得最好的板块」取错——三个失守点都堵了

我先实测了原始接口：

```
视频媒体 +15.21%   净流入 4.39 亿
其他数字媒体 +14.16%  净流入 1.36 亿
机器人 +9.54%     净流入 9.22 亿   ← 净流入排名第 1，但涨幅排第 3
```

**数据源本身是对的**（`po=1` 确实是按 `f3` 降序）。所以「取错」不在接口，在下面三处：

### 失守点 1：模型可能按错了字段排

`sectors` 返回里同时有 `change_pct`（涨跌幅）和 `net_inflow_yi`（主力净流入）。如果按净流入排，「机器人」会排第一，但它的涨幅只排第三——**这就是「涨得最好的板块」取错的直接原因**。

修法：
- 返回里显式加 `sectors_sorted_by: "change_pct"` 与 `sectors_order`；
- `description` 写明「**按涨跌幅 change_pct 排序**」，并注明 net_inflow 只是附带字段；
- `promptHint` 加死禁令：「**不要按 net_inflow_yi 排序**，那会给出完全不同的名单」。

### 失守点 2：接口返回可能不单调

如果东财改了排序参数，或者限流返回了乱序数据，我们会静默把错序当正确。

修法：本地自检，一旦发现 `change_pct` 不单调，**按涨跌幅重排一次**，并在输出里加 `sectors_note` 说明。

### 失守点 3：模型可能没调工具

如果它凭记忆说「今天涨得好的是 AI、芯片」，那是幻觉，不是取错。`promptHint` 已经写了「必须来自这个工具」，这次又加了「引用板块时带涨跌幅数字与领涨股」——**有数字才看得出是不是真取过**。

## 3. 顺带修的

`_Em.guard` 改名为 `_Em.serial`：原来的泛型签名把返回结构写死了，导致 `sectors` 加不了新字段。现在它只负责限速与串行，异常由调用方自己转成 `error`。

## 关于「取错」的诚实说明

我只能确认**代码里不再有排序歧义**，没法在你的手机上复现你当时看到的那次错误——因为不知道它当时调的是哪个模块、按什么排序。

**下次再遇到取错，请把回答里那段板块列表截图给我**，我能一眼看出：是没调工具（没数字）、还是排序字段用错（涨幅低但净流入高的排前面）、还是接口限流（errors 里有记录）。
