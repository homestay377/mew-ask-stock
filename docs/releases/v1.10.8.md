# mew 问股 v1.10.8

## 子智能体：从「只会取数」到「真能干活」

这一版是拆了清水 1.4.2 的安装包、逐条对照之后做的补齐。上一版的子智能体有个硬伤：工具池里只有股票工具，取不到数据就只能编，编完给一句话交差。对着 APK 里的实际工具名和提示词逐条比，缺的不是提示词技巧，是**基础执行能力**和**求助通道**。

### 新增：出网能力 `http_request`

子智能体（和主智能体）现在能直接发 GET/POST/PUT/PATCH/DELETE/HEAD 请求，读网页、调公开 API、下载文件。

- 响应体 512 KB 上限，正文默认返回 8000 字符，超出标 `truncated`；
- 图片、压缩包、APK 这类二进制**不返回正文**，只给大小、mime 与落盘指引——不会把上下文撑爆；
- 非 2xx 不抛异常：抓 404 页面、看错误体是正常需求；
- `save_to` 可以把响应直接落到工作区。

### 新增：受控文件工具

`workspace_read_file` / `workspace_write_file` / `workspace_edit_file` / `workspace_list_dir`。路径归一化后限制在允许的根目录内（应用目录、`/storage/emulated/0`、`/data/local/tmp`、临时目录），越界直接拒绝。只读子智能体只拿到「读文件 + 列目录」。

### 新增：子智能体可以求助、可以申请工具

| 工具 | 作用 | 上限 |
|---|---|---|
| `ask_main_agent` | 缺上下文时问主智能体。主智能体用**无工具**纯文本作答，不会递归派发 | 每任务 3 次 |
| `request_capability` | 缺工具时申请。只批准会话里真实存在的工具；**下一步立即生效** | 每任务 3 次 |

### 新增：团队任务板（依赖图）

分派不再是「并行一批 + 后置一批」两段式，而是一张有依赖关系的任务板：

```json
{
  "assignments": [
    {"task_id": "t1", "agent": "行情侦察", "task": "..."},
    {"task_id": "t2", "agent": "结构审查", "task": "...", "depends_on": ["t1"]}
  ]
}
```

- 依赖全部完成的任务立刻并行开工；
- 前置失败或被跳过时，下游自动 `skipped` 并写明原因，**不再白烧 token**；
- 前置产出按「2500 字/任务、8000 字总量」的预算自动转给下游；
- 老写法 `wait_for_others` 仍然兼容，自动转成「依赖前面全部任务」。

### 新增：`add_team_tasks`

已经分派过、发现还缺活时，往**同一张任务板**追加，可以引用板上已有的 id，不会把做完的活重跑一遍。

**诚实边界**：现在追加发生在分派返回之后，还不会和仍在执行的子任务真正并行——那需要把分派改成后台任务，留到下一版。

### 改：提示词三段硬约束

1. **工作准则**：执行者不是裁判；不许用「我做不到」「无法协助」推诿；先动手验证再说话；真做不到才说明原因和替代方案。
2. **交付格式**：必须按 `【结论】/【证据】/【未完成】` 三段写，不许复述工具原文。
3. **兜底**：跑满 24 步还没结论时，按同样格式声明「取了几次、成功几次、失败哪些」，不再把工具原文整段倒给主控。

### 改：只读边界更清楚

`readOnlyBlockedTools` 增加了工作区写操作。「行情侦察」「资料研究」放开只读（它们本来就要出网取数），结构审查、策略方案、数据核验保持只读，图文标注保持可写。
