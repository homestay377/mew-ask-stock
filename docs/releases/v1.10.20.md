# mew 问股 v1.10.20

## 市场数据：换源 + 补五类之前说「拿不到」的数据

看了三个参考项目之后重做了这一块。核心结论来自 `simonlin1212/a-stock-data` 的封 IP 风险表，我用实测验证了它。

### 1. 指数改走腾讯（不封 IP）

之前 `market_overview` 的指数和板块**全走东财 push2**，而东财是「有风控会封 IP」那一档。我昨天实测连续请求几次后就开始返回空——不是偶然，是设计缺陷。

现在指数走 `qt.gtimg.cn`（腾讯），这是风险表里的「不封 IP」首选。返回是 GBK，按 latin1 收字节后用字段解析，名称用本地表映射，不依赖转码结果。

### 2. 所有东财请求统一限流

`_Em.guard`：串行 + 至少 350ms 间隔。宁可慢一点，也不要把 IP 打死。

### 3. 补上五类数据（全部实测确认可返回真实数据）

| 模块 | 接口 | 实测 |
|---|---|---|
| **limit_up 涨停池** | `push2ex/getTopicZTPool` | ✅ 当日 **28 只**，含连板数、换手、成交额 |
| **margin 融资融券** | `datacenter-web` `RPTA_RZRQ_LSHJ` | ✅ 融资余额、融券余额、两融合计 |
| **billboard 龙虎榜** | `RPT_DAILYBILLBOARD_DETAILSNEW` | ✅ 净买入额、涨跌幅、上榜原因 |
| **hot_ths 同花顺热榜** | `dq.10jqka.com.cn` | ✅ **带题材归因**（`analyse` 字段） |
| **hot_east 东财人气榜** | `emappdata/stockrank` | ✅ 前 N 名 |

**这里要更正我之前的说法**：我曾说「涨停家数没有可靠源」。实际是我只试了东财单入口、且试的日期是空的。换到今天再试，28 只连板数据完整。

### 4. 两项确实不可用，明确写进 `unavailable`

| 项 | 实测结果 |
|---|---|
| 北向资金逐日净额 | 接口返回 `dayNetAmtIn` **全 0** —— 额度披露已经停了，不是接口坏 |
| 连板梯队细分 | 只有每只股的连板数（`lbc`），没有「3板几只、4板几只」这种分组 |

这两项不假装有，写进输出的 `unavailable` 数组里。

### 5. 工具改成模块化

```json
{
  "modules": ["indices", "sectors", "limit_up", "margin", "billboard", "hot"]
}
```

留空表示全开。某个模块失败只影响它自己，`errors` 里写明原因，不拖垮整个调用。

输出示例：

```json
{
  "indices": [{"name":"上证指数","price":3538.95,"change_pct":0.15,"as_of":"2026-11-23 16:14（实时取数，盘中会变）"}],
  "limit_up_count": 28,
  "limit_up": [{"code":"603324","name":"盛剑科技","boards":4,"change_pct":10.0,"amount_yi":6.73}],
  "margin": [{"date":"2026-11-20","financing_balance_yi":21508.62,"change_pct":-0.76}],
  "hot_ths": [{"code":"002148","name":"北纬科技","change_pct":10.04,"reason":"行业原因：特斯拉启动FSD V15首批推送…"}]
}
```

### 6. promptHint 写死禁令

- 市场数字必须来自这个工具，不许凭印象说「今天普涨」；
- `errors` 里的模块就是取不到，如实说明；
- **不许用板块涨幅反推涨停家数**（现在有真实的 `limit_up_count` 了，没理由再推）；
- 北向资金接口返回全 0，不要当有效数据用。

## 数据源优先级（落成注释写进代码）

```
1. 腾讯财经        → 指数（不封 IP）
2. 交易所/官方     → 未接入
3. 新浪/同花顺     → 同花顺热榜
末位. 东财         → 涨停池、两融、龙虎榜、人气榜、板块（全部限流）
```
