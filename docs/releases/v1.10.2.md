# mew 问股 v1.10.2

这一版是「能持续跟着 MewHub 更新」的基础设施，外加一个必须修的错。

## 修：更新检查指错了仓库

`lib/core/release_update.dart` 原来指向上游 `mizaawa/mewhub` 的 latest release。
我们的包名是 `io.github.homestay377.mewaskstock`，上游的 APK 装不上——点「更新」只会得到一个装不了的版本。
现在改指本仓库，检查到的就是能覆盖安装的包。「关于」页的 GitHub 链接也一并改到本仓库。

## 新增：跟上上游的同步机制

本仓库的根提交是「MewHub 快照 + 缠论引擎」的一次性导入，**与上游没有共同祖先**，所以
`git merge` 会把所有同名文件判成 add/add 冲突，`git rebase` 会在改 `lib/stock` 的提交上报 modify/delete。
两条常规路都走不通，于是做了覆盖式同步：

```bash
tool/sync_upstream.sh        # 基于 upstream/main 建 sync/upstream，把我们的层盖上去
```

- 上游**独有**的新文件保留（新能力能进来）；
- 共同路径一律用我们的（包名、MethodChannel、应用标题、缠论引擎不能被静默改回上游的）；
- 上游也改过的共同文件列进「需要人工核对」，想跟进就手动并。

`docs/sync-upstream.md` 写了实测数据：从快照到上游 `b1c09bf` 之间上游改了 15 个路径，
落在共同路径上的 8 个全是品牌/打包相关，因此**这次同步的实际代码增量为 0**——
脚本跑完得到的树与 `main` 完全一致。这条命令以后每次上游发版都要跑一次。
