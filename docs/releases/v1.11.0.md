# mew 问股 v1.11.0

## 手机操控：让问股自己打开 App 看一眼

以前想做"看一下同花顺里我的自选股"这类事，只能：要么接入官方接口（多数 App 没有），要么让用户截图发过来。
这一版加了一条新路——**无障碍服务**：问股可以读当前屏幕、点按钮、输入文字。

### 它能做什么

7 个工具，都在助手页「工具 → 手机与设备 → 手机操控」开关下：

| 工具 | 用途 |
|---|---|
| `mini_phone_observe` | 读屏：元素表（ref / 角色 / 名字 / 坐标 / 可点可输入） |
| `mini_phone_find` | 按文字找元素，长列表省 token |
| `mini_phone_tap` | 点 ref 或坐标（ref 过期能自动退回坐标） |
| `mini_phone_type` | 写输入框（直接 `ACTION_SET_TEXT`，不折腾输入法） |
| `mini_phone_scroll` | 滚动 / 任意方向滑动 |
| `mini_phone_press` | 返回 / 主页 / 最近任务 |
| `mini_phone_open` | 打开 App（包名）或用某 App 打开链接 |

写动作完成后会自动再读一次屏，模型不用多花一轮确认。

### 几个刻意的取舍

1. **没走 Mika 的虚拟屏路线。** 建虚拟屏要 shell 级身份（无线调试 / Shizuku 配对），
   门槛高、容易被系统更新打断；而直接操作主屏只需用户在设置里点一下无障碍开关。
   代价是操作时会占用屏幕——用的时候把问股切后台，让它自己开 App。
2. **Kotlin 只做原子动作，模型循环留在 Dart。** 不搞两套 Agent 打架，工具、记忆、子智能体全都还在原来那套里。
3. **点击时长 90ms、先找可点击祖先。** 行情类 App 大量用自绘控件，太短的 down-up 会被判成滑动，
   文字节点本身不可点——这两条都是踩出来的。
4. **读不到就说读不到。** 无障碍没开时返回 `accessibility_off` 并直接跳到系统设置页，不会假装成功。

### 数据来源的顺位没变

K 线、缠论、行情、板块**仍然走接口**（`docs/data-source-priority.md` 那张表）。
手机操控是"接口拿不到才用"的补充手段，不是把同花顺当数据源——那条路慢、不稳、也不可复现。

### 修掉的两个真 bug（都是这轮 CI 暴露的）

1. `renderScreenForModel` 的去重原来按**整行**比对，而每行的 ref 每次读屏都变，等于没有去重；
   改成按 `角色 + 名字 + 坐标` 去重。
2. 助手页「能力」组变长后把下面的「坐标系显示」挤到屏幕外，旧测试直接点空；
   用例补了 `ensureVisible`。顺手把手机操控开关移到独立分组，能力组不再多一行。

### 验证

### 已知限制

- 只能读**前台**；后台 App 读不到。
- 截图仅安卓 11+，部分 App 禁止截屏时只能靠无障碍树。
- 支付、登录验证码这类页面不自动填，留给用户。
- 操作会占用屏幕，属于主屏方案的必然代价。
